# 现场运行手册

## 首次配置

1. 运行 `./scripts/setup-local.sh`，确认 `.env` 权限为 `600`。
2. 如使用公网入口，在 Cloudflare 创建 named tunnel 和 `play.example.com` 路由。
3. 将 `deploy/cloudflared.yml.example` 复制为 `deploy/cloudflared.yml`，填写 tunnel UUID、凭据绝对路径和域名。
4. 把 `.env` 的 `PUBLIC_ORIGIN` 设为 `https://play.example.com`；`LOCAL_ORIGIN` 保持现场电脑内网 IP。
5. 公网模式用 `./scripts/start-public.sh`；只用现场 Wi-Fi 时用 `./scripts/start-local.sh`。

未配置域名时，优先用 `./scripts/start-easy-public.sh` 做彩排。它通过 SSH 反向隧道连接 localhost.run，不依赖 Cloudflare、无需注册；公网隧道连接本机 `127.0.0.1:3100` 玩家网关，而不是包含管理功能的 `3000` 端口。启动 Godot 前会验证 HTTP、玩家会话、Bootstrap 和 WebSocket。运行期间必须保持终端打开，且不能使用上一次的二维码。失败时运行 `./scripts/diagnose-easy-public.sh`，日志位于 `runtime/logs/`。

Cloudflare Quick Tunnel 只作为备选：`./scripts/start-quick-public.sh`。两种免费隧机域名都不用于正式展演；正式活动应使用有固定域名和可用性保障的服务。

隧道配置只放行 `/join`、静态资源、玩家会话/Bootstrap/QR 和 `/ws`。`/admin`、统计导出和地图管理 API 不通过该公网入口。

## 活动前 30 分钟

1. 笔记本接电源，关闭系统自动休眠、通知弹窗和自动更新。
2. 大屏使用有线 HDMI/DP，声音先以 30% 测试。
3. 运行 `./scripts/preflight.sh`，所有 `[FAIL]` 必须处理。
4. 启动后打开 `http://127.0.0.1:3000/admin`，确认服务、大屏、公网入口和本地入口。
5. 用一部不连现场 Wi-Fi 的手机扫公网码，再用一部连现场路由器的手机测本地码。
6. 完整跑一轮“全场共编”，检查投票确认、执行轨迹和自动切换下一关。
7. 如有条件，在服务运行时执行 `pnpm load-test`。

## 正常运营

- 默认由自动导演持续轮播全场共编关卡。
- 暂停、跳过和重置都会写系统日志。紧急重置需二次确认。
- 不要开放 `.env`、`/admin` 或电脑远程桌面给参与者。
- 活动结束后在管理端导出 CSV，然后用 `Ctrl+C` 停止。SQLite 在 `runtime/game.sqlite`。

## 容器备用

`docker compose up --build -d` 可仅运行权威服务和 Web 三端。Godot 仍在主机运行，环境变量使用 `GAME_SERVER_WS=ws://127.0.0.1:3000/ws` 和 `.env` 的 `SCREEN_TOKEN`。
